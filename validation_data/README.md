# Robustness Validation Data

Auto-generated by `plot_compute.edge_cases.save_edge_cases()`. 33 adversarial market-data snapshots used to stress-test user `compute(ctx)` code **before** a plot is registered.

Each snapshot is run for several consecutive ticks (so per-tick state and the rolling window are exercised, including the cold-start first tick), on an isolated deep copy of the data. A case **passes** only if every tick upholds all four invariants below. Otherwise it is flagged so the bug is caught here instead of in production.

## Invariants checked on every tick

| failure kind | the rule compute(ctx) must obey |
|--------------|----------------------------------|
| `exception` | compute(ctx) must not raise on any market-data shape. |
| `mutated_input` | compute(ctx) must not modify the input snapshot in place — the same ChainSnapshot is shared across all plots in a live tick, so mutating it corrupts every other plot and breaks replay determinism. |
| `bad_format` | the return must be {'value': number} or {'series': {name: number, ...}}. |
| `non_finite` | every returned number must be finite (no NaN / inf). |

> **`mutated_input`** is the subtle one: in the live loop the *same* `ChainSnapshot` object is handed to every active plot, so if one plot writes to `ctx.chain` data in place, every other plot — and every later tick reusing the buffer — sees corrupted data. The harness runs each tick on a deep copy and compares array contents before/after to catch this at validation time.

## Full lifecycle of a plot

```
  user writes compute(ctx) code string
        │
        ▼
  PlotRegistry.create_plot(plot_id, code)
        │
        ▼
  validate_plot_code()  ── 6 stages ──────────────────────────────
     1. syntax        ast.parse
     2. safety        block imports / eval / open / getattr …
     3. contract      compute exists, callable, one arg
     4. robustness    run against THIS battery; 4 invariants/tick   ◀── you are here
     5. result_format {value|series} of finite numbers
     6. performance   <50 ms avg over 100 runs
        │  (any stage fails → ValidationError, plot NOT registered)
        ▼
  PlotRuntime created (status='created')
        │
        ▼
  replay_plot()  — recompute from day start (status='backfilling' → 'live')
        │
        ▼
  compute_one_tick() per 1s snapshot (live)  → output_series → WebSocket
```

## Test cases

### `structural` (8)

| case | options × levels | what it stresses |
|------|------------------|------------------|
| `empty_chain` | 0 × 3 | Zero options in the chain. count()==0 → any division by a count/sum blows up. |
| `single_call_only` | 1 × 3 | Exactly one CALL, no PUTs. Put-side aggregations are empty. |
| `single_put_only` | 1 × 3 | Exactly one PUT, no CALLs. Call-side aggregations are empty. |
| `calls_only` | 6 × 3 | Several CALLs, zero PUTs. put_qty==0 → call/put ratios divide by zero. |
| `puts_only` | 6 × 3 | Several PUTs, zero CALLs. call_qty==0 → put/call ratios divide by zero. |
| `single_book_level` | 8 × 1 | Only L1 exists. Accessing bid_price_l2 / _l3 hits missing levels. |
| `no_book_levels` | 8 × 0 | Book has zero levels per side. Every _l1 access is out of range. |
| `large_dense_chain` | 100 × 3 | 100 options (50C/50P), 3 levels. Stresses per-tick cost and accumulation. |

### `nan` (6)
